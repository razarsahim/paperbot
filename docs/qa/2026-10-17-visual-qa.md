# PaperBot Pro — Visual QA report (2026-10-17)

Method: live inspection in Chrome against a dedicated QA stack running the
current branch (API on 127.0.0.1:8781, `next dev` on :3001, same read-only
state databases), all nine pages, three viewports (1440×900 desktop,
768×1024 tablet, 390×844 mobile). Screenshots in `docs/qa/screens/`.

## Verdict

The dashboard is production-quality for a local research tool: dark theme
consistent, typography/tabular numerals correct, loading skeletons and
designed empty states everywhere, every data section carries a LIVE SIM /
DEMO source badge, and the permanent "PAPER TRADING — SIMULATED FUNDS
ONLY" banner is always visible. Mobile collapses to a hamburger shell and
remains fully usable, including live candlestick charts at 390 px.

- Overview: equity $1,000.00, cash $1,000.00, free margin $900.00

## Defects found and FIXED during this pass

1. API CORS allowed only port 3000, so any other dashboard origin silently
   fell back to DEMO ("backend offline") — origins for :3001 added.
2. Cold-start /api/candles exceeds the UI's 4 s fetch timeout (first ccxt
   call), stranding the Charts page on DEMO until a later poll — candle
   requests now use a 15 s timeout.
3. Analytics pinned validation text hardcoded outdated legacy numbers
   (−2.69%/11 trades); now a static caution plus the live artifact line.
4. "Max drawdown 0.0%" rendered in loss-red at zero — now neutral until a
   real drawdown exists.
5. Stat-tile badges clipped at tablet width (RISK UTILISATION → "LIVE S…")
   — labels truncate, badges never clip.
6. No staleness warning when live data stops updating — the Overview now
   shows an amber "data stale — engine or API not updating" chip when the
   last payload is older than 90 s.
7. Scanner "Funding" column was always "—" (engine never populated it for
   scanned symbols) — now filled from a 10-minute-TTL funding fetch.
8. Engine recorded equity snapshots at frozen marks during a total feed
   outage (fabricated flat line) — snapshots are now skipped (with an
   audit entry) when positions are open and no quote succeeded; the equity
   history keeps an honest gap. Regression-tested in the 3-day soak test.

## Known issues, non-blocking

- Two dev-overlay hydration warnings come from a local Chrome extension
  injecting `bis_skin_checked` attributes into the DOM — external to the
  app; absent in a clean profile and irrelevant to `next build` output.
- Observed ONCE: the pause banner showed the daily-lock variant while the
  API reported no lock. Forensics: the lock flag was never set (zero
  risk-category audit rows ever; the lock path always audits), the API
  returned correct data seconds later, and the render occurred seconds
  after a hot-reload of the very component being edited. Assessed as a
  transient dev-mode Fast-Refresh artifact; not reproducible on stable
  renders; production builds do not hot-reload. Will re-verify on the
  built (non-dev) bundle before any future milestone.
- TradingView attribution logo overlaps the first candles at small chart
  heights (license requires the logo; acceptable).
- Flat single-value equity sparkline doesn't span the full chart width
  (lightweight-charts time-scale fitting; cosmetic, disappears with real
  variation).
